# E0001: unexpected character

Outside comments, a wrela source file holds only ASCII: identifiers (letters, digits and `_`, not
starting with a digit), numbers, operators and punctuation, spaces, tabs and line breaks. Any other
character is an error. Comments may contain any text but a line break.

A line break is `\n` or `\r\n`. A carriage return (`\r`, U+000D) without a `\n` after it is an
error, even in a comment, and so are the other characters Unicode counts as line breaks: vertical
tab (U+000B), form feed (U+000C), next line (U+0085), line separator (U+2028) and paragraph
separator (U+2029). Some editors show them as line breaks and others don't, so a reader and the
compiler could disagree on where a comment ends. A byte-order mark at the very start of a file is
ignored.

Common causes are a letter outside ASCII in a name (`π`, `é`), typographic quotes or dashes pasted
from a document, and invisible characters such as a zero-width or non-breaking space. Invisible
characters are reported by their code point, like `U+00A0`.

```wrela bad
fn area(r: f32) -> f32 {
    let π = 3.14159
    π * r * r
}
```

Spell the name in ASCII:

```wrela fixed
fn area(r: f32) -> f32 {
    let pi = 3.14159
    pi * r * r
}
```
