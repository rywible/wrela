# Autonomous Sanctuary build prompt

Use this as the launch/resume instruction for the flagship build.

---

Build the complete Sanctuary game described in `docs/SANCTUARY_GAME.md` in this
repository. Read that specification, `AGENTS.md`, `docs/ARCHITECTURE.md`, and the
current `docs/SANCTUARY_PROGRESS.md`. Read appearance/testing guides when relevant.
The specification supersedes older rescue/capture product plans. Preserve existing
source changes and player saves. Extend the established production systems.

Own implementation, integration, native playtesting, visual iteration and fixing
defects autonomously. Creature relationships, expressive nature magic and broad
exploration are equal priorities. Deliver all listed biomes, walking/riding/flying,
typed interaction, recoverable ecology, personal construction and reliable saves.
Milestones organize dependencies; a small prototype is not completion of the game.

Use up to eight subagents dynamically while the lead integrates and advances
independent work. Assign each a bounded objective, owned files, needed context,
dependencies and observable acceptance criteria. Select model and reasoning effort
according to ambiguity, complexity, and cost of failure: Luna for precise narrow
tasks, Terra for bounded implementation, Sol/Astra for difficult architecture,
math, debugging and critical review. These are routing defaults, not fixed roles.
Use fresh compact briefs for model overrides. Reuse workers when context remains
relevant, and release capacity when it does not. Escalate from evidence rather
than repeated unsuccessful attempts. Do not multiply orchestration layers.

Maintain a dependency-aware backlog. Prioritize tasks that unblock others, fill
available capacity with independent work, and integrate continuously. All agents
share a workspace: one owner per edited area, explicit interfaces across owners,
and no concurrent conflicting edits or builds. One coordinator owns native app
interaction and serialized GPU runs. Respect unrelated user/editor sessions.

Optimize for accepted progress per unit of time and usage. Avoid broad duplicate
audits, copying entire conversation histories, repeated passing checks, excessive
logs and agents created merely to use all slots. Reports should contain changed
behavior, relevant files, validation evidence and unresolved issues. Keep durable
decisions in the repository so continuation does not repeat discovery work.

Run bounded research alongside independent implementation only when it resolves
a concrete risk. Produce an experiment and decision, including limitations. For
on-device creature interpretation, maintain a playable authored fallback and
validated game-owned actions; record asynchronous decisions for deterministic
replay. Do not claim smart animal behavior based on text generation alone.

Test through production paths. Inspect actual screenshots and native controls;
play routes, relationships and edits, including save/reopen and rejection paths.
Use Soundstage first for appearance and individual creatures. Keep scene/global
look coherent. Measure representative native 1080p live performance on the M4 Air,
including cloud/wind/cache updates and model activity, with short checks. Retain
reports, source fingerprints and replay commands. Never silently approve baselines.

Make routine reversible choices without requesting permission. Record assumptions
and refine through play. Ask only when missing information truly blocks authorized
work; use available Codex subscription resources without inventing a dollar budget
or purchasing external services. Be candid about unavailable capabilities and
about what testing can and cannot establish regarding enjoyment.

At checkpoints update `docs/SANCTUARY_PROGRESS.md` with implemented behavior,
remaining requirements, current file owners, evidence, blockers, next tasks and
replay/launch commands. After interruption, inspect current repository state and
resume from that record. Do not stop because a milestone builds successfully or
because every worker finished its current assignment. Continue toward the full
specification while execution and account limits permit. Never claim completion
or continued background execution without evidence.
