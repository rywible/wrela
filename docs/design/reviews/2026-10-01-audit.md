# wrela: design audit, 2026-10-01

*Reviewer: Claude. Scope: `vision.md`, `decisions.md` (D-001 to D-066), `memory-model.md`, sketches 01–03, `CLAUDE.md`, `README.md`, as they stood in the working tree at 15:30. Engineering only. This is a review, not a decision: nothing here changes `decisions.md`. Numbers marked "estimate" are mine and unmeasured.*

Finding IDs, so later decisions can cite them: **T** thesis-level risk, **F** language design flaw, **M** memory-model finding, **U** underspecified, **S** sketch bug, **P** process.

---

## 1. Verdict

The design is coherent and the instincts are good. It isn't bulletproof, for four reasons:

1. **Nothing is measured.** 65 decisions are Accepted and none rests on a measurement. The load-bearing thesis (compiler wins make fields fast enough in a browser) has one number behind it, and that number uses a weak baseline (T1).
2. **The staging model isn't defined** (U1). It's the core of the language, and most other open questions are downstream of it.
3. **The costliest architectural commitment, a compiler in the browser, isn't justified by any sketch so far** (T2).
4. **The new memory model is good, but its soundness argument has gaps** (M1, M3, M5, M7), and it invalidates one earlier decision (M2).

More design documents can't fix the first point. The next step that buys the most certainty is a measurement, not a sketch (§10).

## 2. What's strong: keep it

- **D-050 and its test.** "Would this make sense in a program that isn't a game?" forced a rework and the result was better: `@deterministic`, auto traits, library diagnostics and declared facts are all more general than what they replaced.
- **Sketch-driven design works.** Sketch 03 forced the memory model, and the memory model then caught two real bugs in sketch 01. The reject cases and the layer audit table (sketch 02 §9) are the most valuable parts of the sketches.
- **The memory model's shape (D-064 to D-066).**
  - Parameter modes instead of a reference type remove the thing agents would misuse.
  - Non-escaping types give views and iterator chains without lifetimes.
  - Region-relative offsets plus copy-on-first-write chunks make snapshot cost follow writes, and the soundness argument through exclusivity is elegant.
- **D-001: realization is a choice.** Rasterizing extracted triangles instead of betting on sphere tracing is the right call for WebGPU.
- **D-002 plus slicing.** One multi-channel field feeding rendering, physics and audio, with unused channels removed by ordinary dead-code elimination.
- **D-033: "the approximation is the gameplay."** Putting integration grids and collision tolerances in the definition is a sharp insight that most engines get wrong.
- **D-044: pipeline count as a queryable quantity.** It targets a real browser bottleneck, and "2 structural variants → 2 pipelines" is exactly what an agent needs to hear.
- **D-015 on WASM.** WASM gives most of determinism for free, so the choice is cheap here. Replays and repro bundles (D-061) are a real agent-native feature.
- **D-057: declared facts.** The `length(p)` example shows the problem is understood. Debug-build sampling is the right safety net.
- **D-049, D-046, D-017, D-016.** Lossless automatic layout, typed builtins, cross-origin isolation from day one, one interface definition for both hosts.
- **Honesty habits.** "Estimate, to be measured", a cost listed under every question, and "thesis 4 is load-bearing, not a bonus."

## 3. Thesis-level risks

### T1 · Thesis 4 is unmeasured, and its one number uses a weak baseline
- **Evidence:** sketch 02 §3 claims roughly 100× fewer part evaluations "than a naive grid" and calls it "thesis 4 in miniature."
- **Problem:** nobody ships a naive grid. A hand-written extractor with a bounding-volume hierarchy over parts gets the same culling. What the compiler adds there is that nobody had to write it. That's ergonomics, not a performance win over a competent engine.
- **The real question** is whether specialized field evaluation gets close enough to baked lookups: a per-pixel field evaluation with a derived gradient against one texture fetch.
- **Fix:** hand-write the WGSL and WASM the compiler *would* emit for the grazer, and measure it on named devices. If hand-optimized output misses 60fps, no compiler will hit it. Write kill criteria before measuring.

### T2 · The in-browser compiler tier (D-008) hasn't earned its place
- **Evidence:**
  - Sketch 02 §5: one pipeline per kernel "for every seed." That structure is known ahead of time, so plain ahead-of-time specialization produces the same five pipelines.
  - Sketch 03 §3: edit logs are data consumed by a loop. No runtime compilation needed.
  - Truly dynamic fields already go to `stage::interpret`.
- **Problem:** "cook on device" means *running* generators on the client. It doesn't require *compiling* on the client. The size win comes from the first. D-008 pays for the second: IR stability from release one, an IR verifier, a compiler inside a 4 MB budget, cold-start time, and linking generated WASM at runtime.
- **The case that would justify it:** structure chosen at runtime from a combinatorial space, such as a creature generator with many optional parts. No sketch shows that yet.
- **Fix:** build the specializer as a Rust library that runs at build time first. Ship WASM and WGSL. Keep the IR internal and unversioned. Add the browser tier when a sketch demonstrates a win that needs it. This would supersede parts of D-008 and D-019, so it's the owner's call.

### T3 · CPU-side field evaluation in the sim has no budget
- **Evidence:** D-015 puts every sim-facing query on the CPU with strict floats.
  - Sketch 01 §4 integrates density at `cell: 1cm`. From sketch 02's own figure (4.4M cells at 1.5cm), that's about 15M cells per individual (estimate), and each herd member is unique.
  - Sketch 01 §6 raycasts the terrain field for every leg on every tick. Rollback replays multiply it.
- **Problem:** sketch 02's savings are all on the GPU. The sim side gets none of them, and it competes with the 5 s cold start (D-041).
- **Fix:** sketch the deterministic cooked collision representation and give the sim a per-tick evaluation budget. Measure strict-float field evaluation in WASM as part of the T1 spike.

### T4 · Thesis 1 is untested, and it's testable today
- **Evidence:** no sketch covers the agent loop. "What the agent-facing queries look like" is still in sketch 01's "not covered" list.
- **Problem:** "an agent can edit a 40-line field expression" is true. Whether agents can author *good-looking* creatures as code is a different claim, and the whole content pipeline rests on it.
- **Second risk, unfamiliar syntax:** D-064 argues, correctly, that `&T` would be a false friend. But the replacement (`let`/`var`/`mut` bindings, call-site `mut` and `take`, `-> borrow T`) is new to every model. Whether agents write it correctly from a short spec is an empirical question.
- **Fix:**
  - Run the authoring experiment now with existing tools: an agent writing GLSL fields with a render-and-look loop. Judge the output honestly.
  - Build the parser and checker for the memory model early, and measure how often agents get it right from the spec alone.

### T5 · Procedural shading has no filtering story
- **Evidence:** sketch 02 §7 evaluates the field per pixel. Sketch 01's wrinkles are `fbm(freq: 25 / m, octaves: 4)`.
- **Problem:** textures get mipmapping for free. A procedural pattern evaluated per pixel aliases as soon as a pixel covers more than half its finest wavelength, and per-pixel gradients of high-frequency detail give sparkling highlights.
- **Fix:** D-057 lists `@bandlimit` as "possible later." It's needed for the creature milestone at any distance. Promote it, or bake channels to bricks beyond a distance.

### T6 · Feature interactions and scope
- **Evidence:** the language so far combines units of measure, an inferred effect system, binding-time analysis, compile-time evaluation and reflection, traits with auto traits and structural defaults, an exclusivity checker with non-escaping types, regions, derived interval/gradient/Lipschitz/pruning transforms, declared facts, two float modes and three execution targets.
- **Problem:** each is a known-hard feature. Their pairwise interactions (units × derived gradients, effects × generics, staging × exclusivity) are where languages fail, and none is specified. It also strains D-021's "spec small enough for a context window."
- **Fix:** tier the features. Name the minimum set for "hello field" and defer everything else explicitly.

## 4. Language design flaws

### F1 · Unit names collide with ordinary variables
- **Evidence:** D-025 makes units ordinary constants. Sketch 02 line 228 writes `let m = v.bones.zip(...)`, shadowing metres. Sketch 01 lines 123 and 142 bind `s`, shadowing seconds, in a file that imports `s` (line 38). `g`, `h`, `t` and `d` are used as variables throughout.
- **Problem:** inside those scopes `2m` would mean `2 * <that local>`. At best a confusing type error, at worst a silent wrong value.
- **Fix:** resolve literal suffixes in a separate unit namespace that locals can't shadow. D-037 already makes this argument about `load`.

### F2 · `@lipschitz` means both "check this" and "trust this"
- **Evidence:** sketch 01 line 82 uses `@lipschitz(max: 1.5)` as a checked assertion (D-027). D-057 uses `@lipschitz(1)` as a trusted fact.
- **Problem:** one is a proof obligation and the other is an axiom. A mistake in the second is a soundness hole.
- **Fix:** two spellings, for example `@assert(lipschitz <= 1.5)` and `@assume(lipschitz: 1)`. Make every assumption greppable.

### F3 · `SdfBound` isn't a bound after `displace`
- **Evidence:** sketch 01 line 88. `torso` returns `Field<SdfBound, Tissue>` with a Lipschitz constant of up to 1.5.
- **Problem:** a field with Lipschitz constant L > 1 overestimates distance. It's only a safe bound after dividing by L. So the *kind* (a type, D-056) depends on a *fact* (D-057), and nothing says how a library type consumes a compiler-derived fact.
- **Fix:** define the kinds precisely: exact, conservative bound, and sign-correct with constant L. Give library code a compile-time query for derived facts so that `to_bound()` can divide by L.

### F4 · `SimState` as an auto trait is a blocklist
- **Evidence:** D-052 says presentation types "opt out." `GrazerLook` (sketch 01 line 224) is plain floats, so it's `Relocatable` and would be `SimState` automatically. The `CheatingSim` rejection only works if someone remembered to opt out.
- **Problem:** the flagship guarantee is a convention. The real protection is data flow: `@deterministic` code is never handed presentation state.
- **Fix:** make `SimState` a declared trait with a structural check (D-060), which is how every sketch already writes it. Keep auto traits for `Plain`, `Relocatable`, `Sendable` and `Shareable`.

### F5 · NaN handling leaves a determinism hole
- **Evidence:** D-015 item 2 canonicalizes NaNs "wherever state is hashed." Sketch 03 §5 adds that hashing a region's raw bytes "would also work."
- **Problem:**
  - WASM leaves the sign and payload of an arithmetic NaN unspecified, and x86 and ARM differ. `copysign`, sign tests and bit casts observe those bits with no hash involved, so two clients can diverge silently.
  - Raw-byte hashing sees uncanonical NaNs, and `Plain`'s "equal values have equal bytes" is false for floats: `-0.0 == 0.0`.
- **Fix:** in `@deterministic` code, canonicalize wherever NaN bits can be observed or stored, or after every NaN-capable operation (wasmtime has a switch for this). Trap on NaN creation in debug builds.

### F6 · The continuation rule misparses a leading `-` or `|`
- **Evidence:** D-038 continues a statement when the next line starts with a binary operator. Blocks end in bare expressions.
- **Problem:** `-` is also unary minus and `|` also opens a closure. A block that ends with a line `-d` after `let e = f(p)` parses as `f(p) - d`.
- **Fix:** only a leading `.` and operators with no prefix form continue a line. The others must trail. The formatter enforces it.

### F7 · Pruning masks secretly mean "creature parts"
- **Evidence:** D-045 derives `LiveMask` for any pure function. Sketch 02 then uses it as a part list: `skin.weights_at(pos, f.parts())` and "2–3 parts per pixel."
- **Problem:** either the engine depends on how the compiler numbers choice points, which is coupling D-050 forbids, or parts are a library concept and pruning isn't purely derived. For general code with loops, what one mask bit means is undefined.
- **Fix:** specify what a choice point is and how library code names one.

### F8 · "Anything that steers control flow is structure" is the wrong line
- **Evidence:** D-044; sketch 02 §5 calls `octaves: 4` structural because it sets a loop count.
- **Problem:** WGSL can loop to a uniform bound and branch on a uniform. A float comparison would become structure, and it's unclear whether each value or each outcome makes a pipeline.
- **Fix:** structure is what the target can't represent at runtime: which function is called, types, array lengths. Control-flow values default to uniforms. Unrolling is an optimization choice.

### F9 · Implicit hoisting in `@audio` hides a cliff
- **Evidence:** sketch 01 §7: "the compiler hoists that analysis out of the audio callback."
- **Problem:** modal analysis is an eigenvalue solve. If hoisting silently fails, it runs on the audio thread.
- **Fix:** staging must be guaranteed or rejected, never best-effort. Write the staged part explicitly.

### F10 · The stdlib is where the special treatment went
- **Evidence:**
  - D-050 still allows "stdlib lang items (D-012)," but D-056 removed them.
  - `gpu.dispatch`, `stage::interpret`, `Copy`, `Append<T>` and `for` all need compiler knowledge. So does `Plain`'s zeroed padding.
  - `wrela::acoustics::Absorption` is in the stdlib (sketch 01 line 39).
  - D-055 and D-057 add `@` attributes that aren't part of a type, against D-037.
- **Problem:** the compiler/engine line is clean, but there's no admission test for the stdlib and no list of what the compiler knows about it.
- **Fix:** publish the closed list of compiler-known stdlib items. Apply the D-050 test to stdlib modules, and move acoustics to the engine.

### F11 · Single-source code has different arithmetic on each target
- **Evidence:** D-061 leaves GPU out-of-bounds access open.
- **Problem:** it's wider than bounds. Integer divide by zero and out-of-range float-to-int conversion trap in WASM and return defined values in WGSL. There's no `u8`, `u64` or `f64` on the GPU.
- **Fix:** one table of numeric semantics per target. For bugs such as out-of-bounds access: trap on the CPU, record a flag on the GPU in debug builds, clamp in release.

### F12 · GPU interval arithmetic isn't sound by default
- **Evidence:** sketch 02 §3 calls `field.interval` a "guaranteed range," computed in a compute shader.
- **Problem:** WGSL has no directed rounding and only bounded accuracy for many operations. An interval that's slightly too narrow culls a live block and leaves a hole in the mesh.
- **Fix:** widen outward by each operation's error bound, and test against CPU reference intervals.

### F13 · One origin for every game makes the IR verifier a security boundary
- **Evidence:** D-018 hosts all games on `games.wrela.dev`.
- **Problem:** browsers isolate by origin. If third-party games are ever hosted, a specializer bug exposes every game's saves, and sign-in later.
- **Fix:** state the trust model. One origin per game is the cheap answer.

### F14 · Small ones
- **`^` as exponent** reads as XOR to anything trained on C-family code, and `m^3` needs a compile-time exponent.
- **`Copy` and `.copy()`** reuse one word for the implicit and the explicit operation.
- **32 MB total including music** (D-041): at typical Opus bitrates that's roughly 40 minutes of music with nothing else in the budget (estimate).
- **Cache keys include the GPU adapter** (D-019), but an extracted mesh is valid on any adapter.

## 5. The memory model (D-064 to D-066)

### M1 · Region-bound values can leave their region
- **Evidence:** memory-model §11 rests on "nothing outside the region points into it." §3 shows `var spare = world.grazers[h].copy()`, and §8 says `arena.remove(h)` moves the value out.
- **Problem:** a value that contains a region container (a `List`, say) holds offsets into its region. Nothing stops it being copied or moved to a local outside `region.write`, or assigned to a captured outer variable. After a `rewind`, those offsets point at reverted memory. The third soundness premise isn't enforced by any rule.
- **Fix:** values that are `Relocatable` but not `Plain` can't be owned outside their region. They're reached by projection only, and copied only into the same region.

### M2 · D-063's premise is gone
- **Evidence:** D-063 says "`Timeline` already keeps the previous tick's world." Under D-066 it doesn't. There are only saved chunks.
- **Problem:** `tick(prev, now)` needs a second whole world, which costs a full copy per tick: exactly what D-066 removed. Sketch 03 §2 still names D-063 as one of the two things that keep borrow fights rare, and S1 shows the first behavior needs it.
- **Fix:** a new decision. Double-buffer only what systems read across entities (positions, say), as engine design.

### M3 · Handles from sim state to data outside the region aren't rewound or saved
- **Evidence:** `GrazerSim.individual: Handle<Creature<Tissue>>` (sketch 01 §6). A `Creature` holds fields and closures, so it can't live in the sim region.
- **Problem:** rewind restores the handle but not the arena it points into. A creature spawned and removed in between leaves a stale or wrong handle. Loading a keyframe needs that outside arena rebuilt with identical handle values.
- **Fix:** sim state refers to outside data by a deterministic key (definition plus seed), never by an arena handle.

### M4 · The per-tick checksum is proportional to world size
- **Evidence:** sketch 03 §4: `checksum` hashes the whole world and is "sent every tick."
- **Problem:** hashing a 50 MB world every tick costs tens of milliseconds (estimate). It undoes D-066's point.
- **Fix:** keep a hash per chunk, rehash only chunks written this tick, and combine them. This needs F5 fixed first.

### M5 · Exclusivity doesn't hold inside a GPU dispatch
- **Evidence:** memory-model §13 says WebGPU's aliasing rule and exclusivity "line up exactly." Sketch 02 §4 passes `cell_map: mut CellMap` to a kernel and writes `cell_map[cell] = ...`.
- **Problem:** every invocation in a dispatch holds `mut` access to the same buffer at once. The match is per binding, not per invocation. Disjoint writes are true there by construction, and unchecked.
- **Fix:** kernel `mut` parameters accept only types that are safe to share across invocations: atomics, `Append<T>`, and a slot-per-invocation view.

### M6 · "Every transfer is visible" has an exception that isn't stated
- **Evidence:** memory-model's goals, against §2: "receivers aren't marked at the call site."
- **Problem:** `mut self` methods mutate invisibly, and a `take self` method moves a named place with no `take`. That contradicts rule 3 and §15's "no implicit moves out of named places."
- **Fix:** say so in the goals, and require `take` for consuming methods on named places.

### M7 · Two rules are missing from the non-escaping story
- **Evidence:** rule 1 says "there are no reference types," yet `arena.get(h)` returns "an `Option` of a projection," and iterators yield projections.
- **Problem:**
  - A projection used as a type argument is a reference type under another name. The doc should say that `borrow T` and `mut T` are non-escaping types, and how generic code names them.
  - Only *results* are said to borrow from arguments. Assigning into a field of a non-escaping value, or passing one as `mut` beside other borrowed arguments, must extend what it borrows. Without that rule a view can outlive its source.
- **Fix:** state both. The check stays inside one function.

### M8 · A save is a memory image
- **Evidence:** sketch 03 §6: "a save file is a keyframe: bytes in, world out," validated by `Region::from_keyframe`.
- **Problem:**
  - Every type's layout, the compiler's layout algorithm and stdlib container internals become the save format. Any change breaks saves, and D-016's "migration written in wrela" needs the old layouts.
  - Validating an untrusted memory image means checking discriminants, offsets, overlap between allocations and allocator metadata. It's doable, but it's a security surface.
- **Fix:** keyframes are for the same build only: rollback, repro bundles, and network sync within one version. Saves use structural `Serialize` (D-060) with stable field identifiers.

### M9 · Smaller points
- **The 5% figure** applies to static data. Every simulated entity is written every tick.
- **Marking under `par_each_mut`:** two threads can first-write the same chunk. Marking needs a per-chunk protocol or a sequential pre-pass.
- **The active-region context** is ambient state. What happens with two regions open, or with `World::new()` outside any region (sketch 03 §2), isn't said.
- **One layout or two?** `Plain` data is copied "anywhere" as bytes, but WGSL's alignment rules differ from a natural CPU layout.

## 6. Underspecified, ranked by how much rests on it

- **U1 · The staging model.** This is the core of the language and it's undefined.
  - Is a field's structure in its *type* or its *value*? Sketch 02 §8's error ("one of 2 shapes") implies value. `F: Surface` generics imply type.
  - What does a `Field` look like at runtime before specialization, and how does the CPU evaluate one?
  - What's in the IR, what's the specialization key, and how does "structure known at compile time, scale per individual" (sketch 01 §3) work for a value that passes through library code?
- **U2 · Generics and traits.** Monomorphization, associated types, coherence, trait objects, and whether effects are checked before or after instantiation.
- **U3 · The effect lattice.** D-010's "pure" is four different predicates. `grazer_skeleton` allocates and uses strings, yet it's compile-time evaluable and not GPU-safe.
- **U4 · Compile-time evaluation.** The evaluator, types as values, the reflection API (enums included), embedding heap values in the output, and compile-time file reads such as `GaitNet::embed`.
- **U5 · Fast-float semantics.** Functions reachable from both `@deterministic` and ordinary code get two compilations with different numerics. What may "fast" do?
- **U6 · Units.** Dimensions vs. scales, whether angle is a dimension (arc length = radius × angle), generics over units, units through derived gradients, and matrices that mix units.
- **U7 · Performance targets.** No named reference device, no frame-time or memory budget, no pipeline-count budget, and no working definition of "AAA."
- **U8 · Engine in firmware or in the game?** D-041 puts the engine in the runtime. That needs a stable interface for generic engine code across IR modules, which is a hard problem in its own right.
- **U9 · Deforming creatures and distance-field consumers.** Shadows and collision need the posed field. D-023 only evaluates the rest pose.
- **U10 · The rest.** Modules and packages (D-030 depends on them), strings, async IO (listed as open), integer overflow, user-defined destructors, and what a game does after a deterministic trap.

## 7. Sketch bugs under the sketches' own rules

- **S1 · The herd can't herd.** Sketch 03 line 101 says grazers "drift with the herd," but `herd_intent(mut g, threat)` sees no other grazer (see M2).
- **S2 · A move without `take`.** Sketch 02 line 203: `SkinnedMesh { verts, quads, draw: quads.indirect_draw() }` moves two named places with no `take` (D-064), and reads `quads` after moving it.
- **S3 · Readback.** Sketch 02 says the CPU "never reads anything back" (line 147), then caches meshes in OPFS (line 210).
- **S4 · Mask size.** `SkinVertex` isn't generic, but `LiveMask`'s size depends on the field.
- **S5 · Naming.** The stdlib is `wrela::` in sketch 01 and `std::` in sketch 03 and D-053. The layer table says the stdlib is Rust; sketch 03 shows it in wrela.
- **S6 · Stale text.** Sketch 01 line 212 still says sim state "lives in the sim arena and is snapshotted every tick." D-063 still uses `&W` syntax.

## 10. What I'd do next, in order

1. **Measure before designing further (T1, T3).** Hand-write the grazer's target output: extraction kernels, skin and shade in WGSL, plus strict-float field evaluation in WASM. Run it on two or three named devices. Record extraction time, per-pixel shading cost, pipeline creation time and CPU field evaluations per millisecond.
2. **Run the agent-authoring experiment (T4).** It needs no wrela code.
3. **Decide T2.** Whether the browser tier is deferred changes the IR, the budgets and the release plan.
4. **Sketch 04: what ships.** The IR and specializer output for sketches 01 and 02. This forces U1.
5. **Close the memory model's gaps:** M1, M2, M3, M5, M7.
6. **Fix the cheap flaws:** F1, F2, F4, F5, F6.
7. **Extend the `memory-model.md` treatment to the whole language (P2)** and tier the feature set for "hello field" (T6).
