# Architecture audit remediation

All eight findings in [the architecture audit](codebase-audit-2026-09-23.md) have implementation and regression coverage. Changes preserve the shared checkout's existing work. The audit describes an earlier frozen snapshot; this report describes the remediation.

| Finding | Implemented result | Main contracts and evidence |
| --- | --- | --- |
| 1. Adoption can fail after editing source | A shared publisher retains intent before mutation, saves browser source before completion, and returns explicit recovery status if receipt or source persistence fails. Identical retries recover the original receipt across restarts. | `packages/authoring/src/work-publication.ts`, fault-injection and restart tests in `work-publication.test.ts`; both Studio and CLI use the coordinator. |
| 2. Alternatives duplicate whole projects | Version 2 work records retain one baseline plus operation batches and candidate identities. Only the selected alternative is materialized. Listing and handoff validate records without replaying alternatives. Version 1 records migrate on read; imported candidates receive explicit verification. | `packages/authoring/src/work-session.ts`, `tools/architecture-benchmark.ts`; 32 alternatives fit in 12.73 MB against the 64 MiB storage budget. |
| 3. Collaboration stops at the process boundary | CLI publication checks document read/write dependency identities under the process lock. Source and durable transaction receipts share one atomic generation pointer. Disjoint edits rebase; overlaps, changed dependencies and reused IDs with different requests fail. Reviewed whole-scene work retains its stronger baseline requirement. | `tools/workspace-transactions.ts`, `tools/bridge.ts`, independent Bun process tests in `tools/workspace-transactions.test.ts`. |
| 4. Games require engine changes | Public `GameModule`, `GameDefinition`, `GameDriver` and manifests define lifecycle, semantic input, inspection, fixed stepping and source-bound saves. The generic player hosts trusted registered modules; the build discovers manifests and exports games. | `packages/runtime/src/game-module.ts`, `games/switch-gate/`, `games/registry.ts`, `tools/game-build.ts`; the second game completes an objective, restores saves and plays from exported local HTML. |
| 5. Discovery and execution disagree | Discovery and execution share an operation capability catalog. Unknown operation/source fields fail with paths instead of disappearing. Review execution has an application-independent package. | `packages/authoring/src/capabilities.ts`, `agent-protocol.ts`, `errors.ts`, `packages/model/src/source-contract.ts`, `packages/review/`; malformed-field and applicability regressions. |
| 6. Catalog, working set and release are conflated | Metadata catalog search and inspection are independent of authoring sessions. Explicit dependency closures retain bounded task budgets. CLI publication merges a task result into the full catalog. Source export and cooking retain only the entry closure plus declared dynamic roots. | `packages/model/src/document-repository.ts`, bridge catalog and CLI commands; a 1,000-definition test checks bounded reads, actual CLI edits with a world exceeding the task budget, and unchanged cooked output after an unused library edit. |

## Verification

The final command logs and benchmark measurements are retained under `output/architecture-remediation-2026-09-23/`. Verification used a frozen source snapshot so concurrent work could continue. Its final fingerprint is `d9c23acdfa2106bee7d1a8403f43451405d42133a05492f1a87bda36fb1fc709`. Like the audit, it excludes the independent field and transport research directories. Browser evidence includes source fingerprints, adapter identity and completion manifests.

- TypeScript, browser TypeScript, package boundaries and Biome: passed. The snapshot has 191 non-blocking lint warnings, mostly non-null assertions; no lint errors are suppressed.
- Full scoped CPU suite: **1,007 passed, 0 failed**, across **220 files**, in 87.51 seconds. The renderer's 142-test subset also passed.
- Production build: Studio, standalone player, compiler worker, offline snapshot and manifest-driven games.

The live shared checkout also passed `bun run check` and `bun run build` after the frozen integration run. Its additional concurrent changes produce 203 lint warnings and one informational diagnostic, with no errors. Full CPU and hardware results above remain bound to the recorded snapshot.
- Hardware integration: **passed**, **19 Studio checks**, Chromium WebGPU on **apple · metal-3**, with Chrome's shader disk cache disabled. Winter Valley's exported first frame completed in **1,007.8 ms**, with four cooked definitions and zero finite source compilations. The route restored all three lanterns and reached home; native input, pause, graphics changes, persistence, mobile layout and failure/restart also passed. - Second game's standalone export: **passed** on the same hardware adapter, also with shader disk caching disabled. The gate opened, the objective completed and restored state was identical. Launch-phase measurements exposed eager compilation of unused material and vertex-layout combinations: renderer initialization alone could take 14.5 seconds. Optional material pipelines now compile on demand while the general pipeline remains available. Compact-relief variants are created only when drawn, and pending specializations cannot publish across device replacement. Regression tests cover deferred creation, reuse, errors and disposal. The five-second launch budget remains unchanged, and the hardware CI commands disable shader disk caching. These are local measurements, not broad-hardware performance claims.

## Boundaries that remain intentional

The catalog schema ceiling is not a measured capacity promise. The current regression workload has 1,000 definitions. Individual task sessions remain bounded to 256 definitions and 16 MiB, while the file bridge also retains per-file limits. Catalog search and individual inspection use metadata/targeted reads; generation publication still validates and writes a complete catalog. A content-addressed storage backend should be justified by measured publication cost before adding it.

Game code is trusted TypeScript registered by the host. Imported JSON cannot introduce executable module URLs. Dynamic source dependencies must be declared in the game manifest. The new game is a small executable architecture proof, not a demonstration of AAA art or game depth.

Large coordinators still exist where they compose lifecycle and domain services. This change establishes ownership and extension points without replacing working simulation or rendering systems wholesale. Artistic acceptance, autonomous agent success rates, token cost and player enjoyment still need evaluated briefs and playtesting; engineering checks do not establish those outcomes.
