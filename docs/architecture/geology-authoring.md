# Terrain and geology authoring

Terrain definitions optionally carry `geology`. Existing files without it retain the same height samples. The model lives in `packages/model/src/geology.ts`; the compiler's height filters, traversal corridors, finite formations, and review are separate modules. Studio corridor controls and shared numeric controls are separate from the main geological editor. Studio exposes these through `GeologyAuthoringPanel`, sharing the standard authoring transaction and undo system.

## Surface composition

The height pipeline is deterministic value noise → polyline landforms → local talus relaxation → strata terracing → protected traversal corridors → existing local interventions. Final flattening and river interventions intentionally take precedence, preserving deliberate traversal edits. The same `terrainHeight`/`terrainNormal` functions drive generated render patches, world sampling, population placement, and the terrain meshes supplied to physics. Adjacent patches sample the same global coordinates, independent of request order. Runtime physics tests raycast the actual installed ridge mesh and verify the compiled cave has a passable tunnel, solid wall, and solid roof.

- Ridges add a smooth profile along an editable polyline.
- Drainage channels subtract that profile. Optional river cross sections separate a flat channel bed, continuous sloping banks, and a floodplain shoulder. Width shares, shoulder depth, and bank asymmetry are authored independently. The path is authored; this is not a watershed solver.
- Cliffs add a finite asymmetric escarpment with a narrow continuous ramp across the oriented line. Optional cliff cross sections expose a talus toe, face width, and crest width. Reversing the points reverses the raised side. River and cliff profiles support seeded continuous variation in their influence width; variation only narrows the authored outer bound, preserving spatial pruning.
- Erosion performs one deterministic four-neighbor talus relaxation. Radius, angle, and strength control the sculpting filter; no hydraulic sediment simulation is implied.
- Strata adjust the height profile into smooth terraces with authored thickness and strength. Material stratigraphy can be authored separately.

Features are capped at 24 paths of 32 points each. Erosion evaluates five base samples, never a recursively expanding erosion stencil. Patch generation and route review use `createTerrainSampler`: it compiles each path into a bounded segment hierarchy, prunes by distance bounds, and memoizes repeated erosion stencil samples using exact numeric coordinates, with a hard 32,768-entry cap. The sampler is batch-local and must be rebuilt after source edits. There is no hidden mutable-source cache. Shared profile evaluation and explicit segment tie ordering preserve the direct analytic height and normal results. Far LODs can underresolve narrow features; inspect near the player and choose widths appropriate to the intended terrain resolution.

## Protected traversal corridors

A corridor has an explicit polyline elevation profile, a core half width, and a blended shoulder. The core is authoritative after noise, landforms, erosion, and strata, so editing a mountain does not erase its authored trail. Both rendering and physics use this same source. Profiles are blended continuously through bends; later corridors take precedence at intersections. Batch samplers precompute corridor influence bounds to skip distant profiles. Existing local interventions remain last so deliberate crossing edits can override a corridor.

**Protect current review route** samples the current terrain at each review waypoint, preserving the first elevation and limiting each following segment to the review's maximum slope. This writes editable source; it is not a hidden solver that continually moves the trail. The panel exposes width, shoulders, and each waypoint's X/elevation/Z. **Use as review route** copies its plan path for current body-clearance, slope and sightline checks. Segment grades do not certify shoulder or corner slopes, and later local interventions can change them; review and playtest the final result. Limits are 16 corridors, 32 points per corridor, and ±5,000 m elevation. Zero-length segments cannot have conflicting elevations.

Wet-bank authoring chooses a drainage feature and controls water half width, fade width, and darkening. This affects vertex color without changing elevation. Removing or changing that drainage clears the dependent bank setting in the same edit.

## True finite caves and overhangs

Caves and overhangs are finite outcrop formations, not heightfield imitations. Each produces an ordinary object field: an exterior minus a tunnel for a cave, or minus a box for an overhang. Plain caves retain their ellipsoid tunnel; stratified caves use intersected, noise-free support planes for a faceted tunnel profile. A protected region expanded by three extraction cells prevents weathering recesses from thinning the wall next to the opening. Optional stratified rock uses the reusable `buildGeologicalRockNodes` construction from `model/geology-rock.ts`: one connected faceted core, four overlapping buttresses, and 2–8 terminating surface fracture scars. Bedding dip and strike form a shared orientation; joint span controls the physical size of the scars. Seeded scars stop near exposed faces rather than cutting entire horizontal seams through the mass. The construction also powers ordinary alpine outcrop assets through `buildGeologicalRockField`, so it is not a separate lookdev-only shape. Scars smaller than the extraction spacing are filtered to avoid undersampled slits. This bounds their scale, not a formal mesh quality error. The final exterior is clipped to the exact source dimensions. Heading rotates the solid and its opening together, including extraction bounds and collision. Optional per-formation rock materials keep terrain soil and rock appearance independent. The extracted triangles and `collision: mesh` enter the existing object render and physics paths. The tunnel opens through both depth faces and reaches below the outcrop base, allowing the terrain to serve as its floor. Width, height, depth, opening ratio, position, heading, material, bedding horizons, dip, direction, joint span, seed, fracture strength, and extraction resolution are editable. There are at most eight formations, each capped at 64 cells.

**Publish formations to worlds** atomically creates/updates objects and replaces their generated instances in every world that uses the terrain. IDs derive from the terrain and formation identities and remain stable across edits. Publishing again updates geometry and placement without duplicating instances. Removing a formation and republishing removes its generated placements; unused object documents remain available for reuse. Manually placed copies are preserved. Conflicting identities and world/document/transaction capacity limits fail before publication. Undo reverses the entire publication.

Terrain-subject previews compile unpublished formations immediately into an isolated scene document map. They replace generated placements in that preview, preserve manual copies, and rebuild geometry and collision after source edits. No project documents or world instances are written. A unique preview world identity prevents gameplay placement overrides from hiding a source edit.

Publishing is an explicit bake boundary: changing a formation in the terrain document does not alter its previously published object or actual world preview until publishing again. Generated objects are detached to permit deliberate downstream editing; republishing replaces their field, material, and collision. The panel states this boundary and review includes unpublished formations.

This does **not** excavate the infinite terrain surface. Underground caves and arbitrary terrain holes require a separate volumetric terrain representation or mesh hole integration. The stratified exterior is a bounded geological construction rather than a measured fracture or erosion simulation; visual acceptance still requires judging its silhouette, scale, and material response. Extreme aspect ratios or very narrow openings can exceed the extraction grid's detail; inspect the compiled surface at gameplay distance before acceptance.

## Review and acceptance

An editable polyline route samples terrain slope and an upright body footprint at up to 512 points, targeting 0.5 m spacing. It reports steep samples against the authored slope threshold and body obstruction by authored formations. The footprint has a center and eight rim samples at the authored body radius (0.35 m by default); five vertical samples at each position test body clearance. Slope uses the maximum footprint sample and overhead clearance tests the entire rim. Bounding-box rejection keeps distant formations out of expensive field queries. These are finite samples, not a continuous swept-volume guarantee. Other world objects, animated objects, and published object overrides are outside this analysis. Endpoint sightlines test terrain and formations with at most 512 samples. The UI exposes the actual route sample spacing and calls the review approximate.

To review a scene:

1. Add a ridge and drainage path; inspect their surface and silhouettes in the terrain preview.
2. Set the review route, protect it as a corridor, then resculpt the ridge and verify its width and elevation remain authoritative. Inspect transitions at corners and crossings.
3. Add a cave or overhang, position it, and use **Rest on terrain**. Inspect its live terrain preview before publishing.
4. Publish, then inspect the linked world and traverse the opening with the player to verify both rendering and collision.
5. Edit the review route across the wall and then through the opening. Compare obstruction reports and endpoint sightlines.
6. Republish an edit and undo it to verify the full placement/geometry transaction.

Automated coverage checks schema/workload limits, protected widths and grades, corner continuity, body radius, rotated and seeded layered solids, each landform, terrain normals, filter behavior, intervention precedence, legacy equivalence, adjacent-patch seams, actual cavity/solid field samples and extracted meshes, route/sightline diagnostics, publication/republish/removal, identity protection, and undo/redo. These checks establish a functional authoring path; they do not establish AAA artistic quality or replace playing the resulting world.

## Workload evidence

A local CPU spot measurement on 2026-09-22 used all 24 landforms with 32 points each, erosion enabled, four noise octaves, and a 32 × 32 cell patch (1,089 vertices). Removing a square root/hypotenuse evaluation from each segment lowered this case from approximately 203 ms to 58–93 ms per patch in three consecutive runs. A subsequent compiled segment hierarchy and bounded exact-coordinate stencil cache reduced the same case to 11.8 ms cold and 4.9–5.2 ms warm in the recorded eight-run check. Reproduce with `bun tools/geology-benchmark.ts`. Equality tests compare compiled and direct height/normal samples for mixed shapes, intersecting paths, degenerate segments, domain boundaries, and source changes. This is a maximum-source stress fixture with spatially separated paths, not a browser frame-time benchmark or a worst-overlap bound. Larger scenes still require budgeting and profiling before acceptance.


## Terrain lookdev

`bun tools/terrain-lookdev.ts --revision=aaa-authoring` records the existing alpine landscape, gameplay and bedrock views, then a dedicated geology authoring study with generated **formations**, a **passage** interior, and a **protectedTrail** view. All outcrop and formation views use the shared geological field construction. Two held-out sources, **cross-bedded** and **confined**, vary seed, bedding orientation, joint span, aspect ratio and river profile, and each records formation and passage views without special-case geometry. The saved project supports reopening and editing the exact inputs; `traversal.json` and `held-out-traversal.json` record sampled route reviews and `capture.json` records GPU capture completeness, diagnostics and adapter. Captures require hardware rendering. A successful capture and passing traversal review establish functioning tools; neither alone establishes AAA visual quality.

The study route has 90 samples, no steep or formation-blocked samples, a maximum footprint slope of approximately 4.76°, and a clear endpoint sightline before any user edits. Physics regression checks independently verify the protected corridor surface, rotated cave passage, solid wall and roof using the installed collision mesh.

The extended CPU stress fixture is `bun tools/geology-benchmark.ts --corridors`: it adds all 16 corridors with 32 points each to the existing 24-landform/erosion case. On 2026-09-22 the eight-run local check measured 18.9 ms cold and 10.4–13.5 ms subsequent patches at 32 × 32 cells. This measures synchronous terrain generation, not GPU or browser frame time, and should not be generalized to all hardware or worst-overlap paths.

The first stratified-shell lookdev iteration exposed two defects: rectangular silhouettes read as stacked masonry, and inclined layer cuts allowed thin sky leaks through the walls. The generator was changed to an asymmetric mass with lower shoulders and explicit layer-overlap margins. A field regression now samples through bedding boundaries in a wall, and physics tests retain the passable tunnel and solid roof. This is a visual-driven correction; it does not by itself certify finished rock art.

## Connected bedrock and cross-section iteration

The prior capture above drove a structural revision: the ellipsoid shell and overlapping slab layers were replaced with connected bedrock, and the alpine river now uses a bed/bank/floodplain cross section rather than a neighboring raised ridge. The alpine path is one continuous elevation corridor rather than overlapping flatten circles. Studio exposes the optional profiles and bedding controls; changing a feature kind clears an incompatible cross section in the same undoable edit. Existing sources without a profile retain exactly the previous height samples.

Focused tests cover connected interior columns over five seeds and three bedding inclinations; source bounds; compiled/direct profile equality; first-derivative continuity across river bed, bank and shoulder transitions; patch height/normal seams; compiled snapshot isolation; protected grades; and held-out cave clearances and collision meshes. These establish construction and traversal properties. Fresh hardware captures remain the acceptance authority for the new silhouettes, ground contact, weathering, and banks. The earlier below-AAA verdict remains preserved as evidence; passing these tests does not supersede that visual verdict.

`bun tools/geology-benchmark.ts --profiles --corridors` exercises 24 mixed river/cliff profiles with seeded variation, 744 path segments, erosion, and all 16 protected corridors. The 2026-09-22 local eight-run check measured 23.4 ms cold and 11.0–15.2 ms subsequent 32 × 32 cell patches. This is synchronous CPU generation under maximum source counts, with the same limitations as the earlier measurements; no GPU or frame-rate claim follows.


### Passage geometry review and bounded correction

The actual hardware images from `output/authoring-lookdev/1790115555797-30193/source/output/terrain-lookdev/v1/` showed thin flaps at the left passage ceiling and jagged lips around recesses in both the main and cross-bedded formations. These defects survived the earlier connected-interior checks: all six extracted formation meshes had one connected triangle component, so component count alone did not detect the problem. The probable cause was near-tangent intersections between noisy rock cutters and noisy exterior surfaces, together with shallow scars close to the cave wall.

The correction uses smooth cutters whose centers remain outside the exterior envelope, keeping recesses open to the exposed face; the faceted tunnel now uses clean support planes; and an expanded opening protects the neighboring wall from weathering cuts. A dense regression compares the weathered and intact solid next to the opening across all three source variants. This is a bounded geometric correction, not a general mesh-quality certificate. The capture tool also records `passage-normals.png` to distinguish the dark floor's lighting from geometry defects. Fresh beauty and normal captures must judge the correction.
