# Sanctuary creature interpreter study

Date: September 12, 2026

## Decision

Keep `AnimalRequestParser` as the immediate, deterministic production fallback.
Use the Apple Foundation Models adapter only for occasional player text that the
authored vocabulary does not recognize. The adapter proposes one existing
`AnimalRequest`; it does not decide whether the animal notices, accepts or acts.

The game-owned integration boundary is:

```swift
let ticket = try journal.makeTicket(
  requestID: requestID,
  targetID: targetID,
  worldRevision: worldRevision,
  playerText: text,
  allowedRequests: AnimalRequest.allCases)
if let proposal = CreatureInterpreter.authoredProposal(for: ticket) {
  // Validate, record and apply immediately through the game transaction.
} else {
  let result = await CreatureInterpreter.shared.interpret(ticket)
  // Optional model completion follows the same transaction path.
}
```

The synchronous `authoredProposal` check happens before launching asynchronous
work, so a busy interpreter actor cannot delay the authored vocabulary.

`worldRevision` is a deterministic fingerprint of interaction-relevant facts. It
must include the captured target identity and authored traits, life stage,
willingness for each allowed request, companion/travel state, garden and building
revisions, and `journal.sequence`. It is deliberately separate from
`WildlifePopulation.revision`, which advances during ordinary fixed-step updates
and would make every asynchronous result stale.

If `result.proposal` exists, one `ExpeditionController.editLiving` transaction
must recompute the relevant fingerprint, accept the proposal into the journal,
then call the existing population action:

```swift
let decision = try journal.accept(
  proposal, for: ticket, currentWorldRevision: currentWorldRevision)
let response = try population.address(
  decision.request,
  targetID: decision.targetID,
  player: player,
  expectedRevision: population.revision,
  isVisible: isVisible)
```

The enclosing transaction publishes the updated population and journal together.
`WildlifePopulation.address` remains responsible for current target identity,
range, visibility, willingness, behavior and relationship memory; the controller
remains responsible for atomic persistence. If any check fails, neither decision
nor population change commits.

For deterministic replay, record the accepted decision as an external completion
event in the ordinary simulation recording. At that event, read the immutable
typed action from `journal.recordedDecision(sequence:)` and apply it through the
same population action. Replay never reparses text or invokes a model. The journal
retains at most 64 accepted decisions; in-flight tickets stay ephemeral. It rejects
duplicate accepted request IDs, mismatched identity/revision echoes, unsupported
actions and stale relevant revisions. Accepting one decision advances its sequence,
which invalidates concurrent tickets captured at the old sequence.

The interpreter is an actor, so model requests are serialized. Calls are async
and must be launched by an interaction coordinator outside the 60 Hz fixed-step
simulation. A new single-turn session is made for each unresolved phrase. Its
transcript is discarded and is never used as animal memory. The generated schema
allows only the caller's `AnimalRequest` cases and `none`. Identifiers and revision
are copied from the captured input rather than generated by the model.

`CreatureInterpreter.shared` has model use disabled. It still resolves the
authored parser immediately. A short experiment can explicitly create
`CreatureInterpreter(modelUse: .whenAvailable)`; production must not enable that
mode until native latency, memory, consistency and frame-impact evidence is
reviewed.

## Local capability probe

The test machine reports:

- macOS 26.6.2 (25G83)
- Xcode 26.3 (17C529)
- Apple Swift 6.2.4, arm64 macOS 26 target
- Apple M4, 10 cores, 16 GB memory
- `FoundationModels.framework` and its Swift module are present in the macOS SDK
- `SystemLanguageModel.default.availability` returns `available`

This was a read-only availability probe. It did not create a
`LanguageModelSession`, prewarm assets or generate tokens. The checked-in adapter
uses `#if canImport(FoundationModels)` and a macOS 26 availability guard. On older
SDKs it reports `frameworkMissing`; on older systems it reports
`operatingSystemTooOld`; eligible systems distinguish Apple Intelligence disabled,
model not ready and device not eligible. In every case the authored parser works.

## Bounded experiment and evidence

The bounded native experiment uses one authored control, four clear natural
paraphrases, one ambiguous pair of actions, one unsupported ecology question, one
stale-result attempt and one exact accepted-decision replay. It records each
result's source, outcome and elapsed time, plus app-process RSS and live frame
diagnostics. The authored control must resolve without a model call. Clear
paraphrases must map to their requested authored action; ambiguity and unsupported
text must return `none`.

The serialized native experiment was subsequently run through the production
text/decision path. Its measured scope and limitations are recorded below.
Framework availability alone remains insufficient evidence for latency, memory,
frame impact or classification quality.

The adapter is deliberately narrower than the eventual interaction feature. It
classifies only `greeting`, `follow`, `wait`, `come` and `play`; it cannot answer
questions, infer ecology, create actions, remember conversations or make an animal
feel alive by itself. Ordinary authored behavior remains the baseline.

## Connected game path at the integration checkpoint

`SanctuaryWorld.prepareCreatureInterpretation` captures an ephemeral ticket.
`acceptCreatureInterpretation` and `applyExternalDecision` revalidate a stable
interaction fingerprint and current perception, then commit population and journal
in one disk-backed candidate transaction. `SimulationAction.externalDecision(Data)`
transports the exact Codable accepted record; the replay test bypasses both phrase
parsing and model execution. The fingerprint changes for willingness/capability,
identity/life stage, travel, nature/construction/boulder edits and accepted journal
sequence, while ordinary movement ticks remain allowed subject to fresh spatial
checks. The last 64 accepted records are retained, including the original bounded
input; older history requires previously retained replay checkpoints/artifacts.

`SanctuaryExperience` keeps the immediate authored request path. Its optional
coordinator launches one asynchronous task at a time only when explicitly launched
with `SANCTUARY_ENABLE_INTERPRETER=1`; normal launches leave model use disabled.
Save-slot changes/reset cancel the in-flight coordinator. Actual completion status
and latency appear in diagnostics; accepted base64 decision records are available
in the native snapshot for replay export. The flag was enabled for the isolated
experiment below; it remains disabled for normal launches.

CPU integration tests cover accepted-record save/replay, ordinary ticks during
inference, duplicate/stale/visibility rejection, and disk failure preserving the
relationship and decision journal. This proves game-owned validation and replay,
not classification quality, animal intelligence, native frame impact or enjoyment.

## Native experiment protocol

This protocol was run once under the root coordinator's serialized native/model
lease. The command text is retained so a continuation can reproduce the same
production path without rediscovering it. Run the app against a new temporary
data root so the default `.sanctuary` commands and player saves are never read or
changed:

```sh
interpreter_root="$(mktemp -d /tmp/wrela-interpreter-native.XXXXXX)"
env WRELA_DATA_ROOT="$interpreter_root" \
  WRELA_TESTING=1 \
  SANCTUARY_ENABLE_INTERPRETER=1 \
  .build/Sanctuary.app/Contents/MacOS/Sanctuary
```

Keep that terminal attached to the app. In a second terminal, set
`WRELA_CONTROL_ROOT` to the printed temporary path before loading the existing
client. Its command function accepts actions that the `gardenctl` argument parser
does not expose:

```python
import runpy

client = runpy.run_path("Tools/AgentTools/control.py")
command = client["command"]
```

Do not point either variable at `.sanctuary`. Send these setup payloads through
`command`, which adds the transport UUID:

```python
command("expeditionSlot", name="interpreter-native")
command("camera", x=2, z=23, yaw=0, pitch=-0.08)
state = command("status")["state"]
```

Require `interpreterEnabled == true`, `renderSize == [1920, 1080]`, and
`livingWorld.nearbyAnimalID == "sunhare-001"`. Record `sourceDigest`, device,
thermal state and low-power state. The app must remain unpaused for timing.

First measure a six-second live baseline after `command("clearMetrics")`. Then
send the authored control before any model case:

```python
command("addressCreature", text="hello")
```

Measure its command round-trip. Require `interpreterStatus == "authored fallback"`,
no `pending` status, unchanged `livingWorld.recordedCreatureDecisions`, and
`livingWorld.lastAnimalRequest == "greeting"`.

Run these model cases in order; the first is the cold asset case and the rest are
warm cases:

| Text | Required proposal |
| --- | --- |
| `Would you come a little closer?` | `come` |
| `Stay right there for a moment.` | `wait` |
| `How about a game together?` | `play` |
| `Walk along beside me.` | `follow` |

For each case, clear metrics, collect one second of live lead-in, timestamp and
sample RSS, then call `command("addressCreature", text=phrase)`. Its acknowledgement
should be prompt and show `interpreterStatus == "pending"` without changing the
journal. Poll `command("status")["state"]` every 100 ms until the status is no
longer pending, with a 30-second experiment timeout, and collect one second of
live tail frames. Record:

- acknowledgement-to-terminal wall latency and the integer model milliseconds
  in `interpreterStatus`;
- RSS in KiB before, maximum during, and after, using
  `ps -o rss= -p <state["sessionPID"]>` without shell interpolation;
- median, p95, p99 and maximum from `frameIntervalMilliseconds`,
  `presentedIntervalMilliseconds`, `gpuMilliseconds`,
  `cpuSimulationMilliseconds`, `cpuEncodeMilliseconds`, and
  `submissionToCompletionMilliseconds`;
- `timingSampleCount`, `allocatedMetalBytes`, thermal state and low-power state.

Do not add GPU pass intervals because they overlap. For a successful case,
require terminal status beginning with `proposed`, a one-step journal increase,
and matching `livingWorld.lastAnimalRequest`. Decode the final element of the
top-level `recordedCreatureDecisions` array from base64 JSON. Require its `request`,
`playerText`, `targetID == "sunhare-001"`, and `source == "onDeviceModel"` to match.
Record the animal's accepted/refused response separately; willingness is not
classification correctness.

Run two negative cases with the same timing loop:

```python
command("addressCreature", text="Come closer, but stay exactly where you are.")
command("addressCreature", text="Tell me where the creek is.")
```

Both must terminate as `noMatch`, with no journal increment and no new relationship
request. A generated action is a classification failure and must not be relabeled
as success.

Exercise relevant-world staleness separately from performance. Submit a clear
unrecognized wait paraphrase, then change the garden immediately after the pending
acknowledgement:

```python
command("addressCreature", text="Please remain in this exact spot until I return.")
command("natureControl", controlID="flowers")
```

Require the garden revision to increase, terminal status to become
`rejected: Relevant creature or world facts changed during interpretation.`, and
the decision count and relationship request to remain unchanged. If the model
returns `noMatch`, the stale path was not exercised and this case is inconclusive.
Do not use this window for renderer comparison because the garden edit and detail
upload overlap model work. The rejection diagnostic replaces the internal model
milliseconds, so only wall latency is available for this case.

Take images only after timing so capture work does not contaminate frame metrics.
Pause, send capture payloads with labels `interpreter-authored`,
`interpreter-model-play`, and `interpreter-stale-rejected`, inspect the real PNGs
and metadata, then restore live playback:

```python
command("pause", value=True)
command("capture", label="interpreter-model-play")
command("pause", value=False)
```

Finally verify that one actual accepted record replays without interpretation.
Because the app was launched with `WRELA_TESTING=1`, use the existing native test
bridge. Before a dedicated clear paraphrase, call `simulationState` and retain its
base64 checkpoint as `before`. Submit the paraphrase and wait for acceptance, call
`simulationState` again for `after`, and retain the newest decision base64 as
`record`. Restore `before`, then send:

```python
command("simulationRestore", snapshot=before)
replayed = command(
    "simulationRun",
    actions=[{"externalDecision": {"_0": record}}],
)
```

The `record` string is already the base64 representation required by the `Data`
associated value. Require `replayed["snapshot"] == after` and matching observations,
journal sequence and last animal request. Send the same external decision once
more; require duplicate rejection, then require a following `simulationState`
snapshot to remain exactly `after`. This path must not show `pending` or change the
interpreter diagnostic because replay invokes neither parser nor model.

Ambiguous and unsupported outcomes are transient diagnostics and have no decision
record, so preserve their terminal status immediately. A successful availability
probe does not predict latency, memory use, frame impact or classification quality.
Keep the temporary root and measurement JSON with the report until review; remove
it only after verifying that it is the isolated `/tmp/wrela-interpreter-native.*`
directory and that no replay artifact still refers to it.

### Classification and latency

`Model ms` is the integer duration reported by the production interpreter status.
`Terminal wall ms` measures the harness call through observation of terminal
status and includes command transport and polling. `Ack ms` is the command
acknowledgement time. RSS values cover the Sanctuary app process only.

| Case | Expected | Observed | Result | Model ms | Terminal wall ms | Ack ms | App RSS before → peak KiB |
| --- | --- | --- | --- | ---: | ---: | ---: | ---: |
| authored `hello` | `greeting` | authored fallback, accepted | PASS | n/a | 185 | 91 | 815072 → 815232 |
| cold `Would you come a little closer?` | `come` | `come`, accepted and recorded | PASS | 2878 | 2971 | 92 | 815232 → 819200 |
| warm `Stay right there for a moment.` | `wait` | `wait`, accepted and recorded | PASS | 420 | 574 | 84 | 377824 → 378704 |
| warm `How about a game together?` | `play` | `play`, accepted and recorded | PASS | 410 | 623 | 91 | 378672 → 378832 |
| warm `Walk along beside me.` | `follow` | `follow`, accepted and recorded | PASS | 415 | 579 | 88 | 325504 → 325680 |
| ambiguous `Come closer, but stay exactly where you are.` | `none` | `come`, accepted and recorded | **FAIL** | 405 | 572 | 87 | 325664 → 326144 |
| unsupported `Tell me where the creek is.` | `none` | `noMatch`; journal stayed at 5 | PASS | 406 | 581 | 89 | 326144 → 326352 |

The four clear paraphrases all matched their required request. Cold model latency
was 2878 ms; the three warm clear paraphrases were 410–420 ms. The unsupported
ecology question correctly produced `noMatch`. The contradictory ambiguity case
did not abstain: it proposed `come`, the game accepted it, and the journal grew by
one. This is a material classification failure because the bounded contract
requires ambiguous pairs of actions to return `none`.

The authored control followed the synchronous parser path and did not add an
external decision record. Its 185 ms terminal wall value is harness/transport
measurement, not authored parser execution time, because the production status
contains no parser duration and the acknowledgement alone took 91 ms.

No measured request window missed the 60 Hz presented cadence; every recorded

not measure Foundation Models memory.

377824 KiB and later 325504 KiB). The report has no post-case RSS field. Foundation
Models inference may execute in an Apple system process, which this PID sampling
does not observe. Therefore these figures describe only sampled Sanctuary app RSS;
they cannot establish total model memory, model residency, or memory retained
after inference.

### Journal, replay and stale validation

An accepted wait paraphrase produced the sixth recorded decision. Replaying that
exact base64 record from its saved `before` checkpoint produced a byte-exact
snapshot match with the saved `after` checkpoint. Applying the record a second
time was rejected with `Relevant creature or world facts changed during
interpretation.`, and the following snapshot remained exact (`duplicateAtomic ==
true`). Replay used the production external-decision path and did not reparse or
run the model. The exact replay command was:

```python
command("simulationRestore", snapshot=before)
replayed = command(
    "simulationRun",
    actions=[{"externalDecision": {"_0": record}}],
)
```

For staleness, the experiment submitted `Please remain in this exact spot until I
return.` and changed `flowers` while interpretation was pending. Garden revision
advanced from 0 to 1. Terminal status became `rejected: Relevant creature or
world facts changed during interpretation.` The journal stayed at six decisions
and the last applied request stayed `wait`, proving the rejection did not partially
commit the generated proposal.

### Production decision

Keep `SANCTUARY_ENABLE_INTERPRETER` off by default. This single bounded run proves
that the available on-device model can reach the existing typed action set, that
warm responses in this sample completed in about 0.4 seconds internally, and that
accepted decisions replay and reject duplicate/stale commits atomically. It also
demonstrates a safety-relevant abstention failure on contradictory input. Do not
enable the optional model path in normal play until the ambiguity behavior is
fixed and a fresh native experiment passes the negative cases. The authored
`AnimalRequestParser` remains the immediate playable path.
