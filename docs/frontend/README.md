# Frontend API and build contract

The workspace uses Rust 1.98.1 and LALRPOP/lalrpop-util 0.23.1. `Cargo.lock` fixes dependency resolution. Handwritten `frontend/src/grammar.lalrpop` and typed actions are separate from generated Rust in Cargo's `OUT_DIR`. Generation fails on grammar conflicts; generated files are never edited.

`source`, `token` and `lexer` own/classify input bytes. `syntax` models declarations, types, statements and expressions with typed variants and tape references. `parsing` is the generated parser boundary and bounded recovery. The public frontend composes diagnostics and controls syntax admission. External serialization and the CLI inspect these domains without making JSON the syntax model.

Run `cargo test --locked`, `cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets --locked -- -D warnings`. The regeneration script compares generated bytes after builds from independent grammar paths on this machine. Cached dependencies allow `--offline`; installing the pinned Rust toolchain and populating Cargo's cache are separate environment setup steps.

The independent corpus defines intended outcomes and structural relationships; parser output snapshots do not define language behavior. Corpus identity/digest checks protect missing cases. Negative structural controls establish that erased roles/markers, incorrect kinds, impossible ranges and containment errors fail validation.

`python3 scripts/verify-generation.py` compares generated grammar bytes across two fresh source paths. `python3 scripts/verify-conflicts.py` deliberately injects an ambiguous expression grammar into a temporary copy and requires generation/build failure. Both scripts leave the production grammar unchanged.

The AST performs no source normalization: grouping nodes, optional trailing separators, authored identifier spelling, numeric/string spelling and absent-versus-present empty enum payload parentheses are retained. Strings are syntax tokens; decoding escapes into runtime values belongs to later phases. The CST is a recursive inspection projection of this typed model, with explicit child roles and tape references. Its root full range includes exterior trivia; other full ranges equal their significant ranges and include interior gaps. Trivia belongs to the source tape rather than being reassigned to neighboring declarations.

`max_depth` also applies a conservative structural complexity budget before parsing: active grouping plus operators/postfixes in each expression scope, and else branches in a chained conditional. Commas/statement boundaries reset their own scope. This intentionally rejects pathological long flat chains before constructing recursively owned syntax. It is a safety contract rather than a claim that each counted element maps to one AST level.

The feature reference is [First Wrela Source Frontend](https://chatgpt.com/space/page_9310020266848191aa8ef0d1313fbc30); durable implementation tracking is [KAN-7](https://wrela.atlassian.net/browse/KAN-7). The frozen independent seed and its approval-status metadata are retained under `frontend/tests` with digest/identity checks.

For direct use, run `cargo run --locked -p wrela_frontend -- frontend/examples/particles.wr`, or add `--json` to inspect the typed syntax, recursive CST roles, diagnostics and source tape. The particle example is the independently authored V01 program. Reading stdin is supported; exit status 0 means syntax admission, 1 means rejected source, and 2 means I/O/usage failure. The library exposes `parse`, configurable `parse_with_limits`, inspection methods and consuming `admit`; admitted documents expose immutable source/syntax references.
